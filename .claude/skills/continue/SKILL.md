# /continue：推进当前里程碑

用户说“继续当前进度”时执行本流程。**不要重新询问背景**：背景全部在仓库里。

补充说明（可能为空）：$ARGUMENTS

## 1. 读取状态

按顺序阅读：

1. `CLAUDE.md`：项目约束与不变量；
2. `docs/progress.md`：自主推进设置（**这是用户的授权范围，严格遵守**）、当前状态、子任务断点、待决事项、交接日志最后几条；
3. `docs/roadmap.md`：当前里程碑包含哪些步骤，以及它们的依赖和验收标准。

也可以运行 `python3 tools/workflow/hooks.py summary` 查看摘要。

## 2. 处理用户刚给出的决定

如果本轮消息或上一轮对话中，用户对某个“待决”事项给出了决定，先按 `/decide` 的格式（见 `.claude/skills/decide/SKILL.md`）把它记入 progress.md，再继续。

## 3. 循环推进当前里程碑

当前里程碑 = progress.md 中的“当前里程碑”。循环执行：

1. 按 `.claude/skills/step/SKILL.md` 完成**一个**步骤，包括其中的交付与合并；
2. 步骤合并后，如果当前里程碑还有未完成的步骤，回到第 1 步；
3. 以下任一情况出现时，退出循环：
   - 当前里程碑的所有步骤都已 ✅；
   - 剩下的步骤全部被阻塞（等待用户决定、缺密钥、域名被拦截、超预算、PR 等人工合并）；
   - 触发了 `step` 流程中的任一“必须停下”条件。

**不要越过当前里程碑。** 每个步骤交付时，ship.md 已经把 progress.md 的指针移到下一个步骤（可能属于下一个里程碑）。所以“当前里程碑”变成新的里程碑时，就说明上一个里程碑已完成，停下汇报即可。

在云端会话中，等待 CI 时会结束本轮，CI 事件或兜底检查唤醒后继续这个循环。继续前先重读 progress.md。

## 4. 汇报

停下时用下面的格式回复用户（简体中文，简洁）：

```
## 里程碑 M0.1 进展：已完成 / 进行中 / 被阻塞

**完成的步骤**
- P0-01 验证脚手架：PR 链接；演示方式（命令或产物路径）

**验证**：各步骤验收标准的结果，make arch-check 的结果

**费用**：本里程碑共计 ¥x

**需要你做的事**
- D-001 ……（候选、推荐）→ 回复 `/decide D-001 B` 或直接说
- 在云环境设置中添加环境变量 XXX_API_KEY（新会话生效）

**遗留与技术债**：……

**下一步**：下个里程碑 / 步骤是什么；说“继续当前进度”即可开始
```

没有需要用户做的事时省略该段。不要罗列过程细节，细节在 PR 和交接日志里。
