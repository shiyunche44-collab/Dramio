# /decide：记录用户的决定

用户输入：$ARGUMENTS

待决事项在 `docs/progress.md` 的“待决事项”表中。只有用户能做决定：本命令只把用户**明确说出的**决定记下来，不替用户补全或推断。

## 输入为空：列出待决事项

列出所有状态为“待决”的事项：编号、步骤、问题、候选（含产物路径）、推荐与理由。结尾提示回复方式，例如 `/decide D-001 B`、`/decide D-001 按推荐`、`/decide 全部按推荐`。不修改文件。

## 输入不为空：记录决定

支持的写法：

| 写法 | 记录为 |
|---|---|
| `D-001 B` | 选择候选 B |
| `D-001 按推荐` | 采用该事项的推荐项（在“决定”列写出推荐项的具体内容） |
| `D-001 B，但背景改成夜景` | 选择 B，并附带修改要求 |
| `D-001 都不行：人物年龄再小一点` | 驳回全部候选，附带重做意见 |
| `全部按推荐` | 所有“待决”事项都采用推荐项 |
| 多个事项用分号隔开，如 `D-001 B；D-002 按推荐` | 逐项记录 |

对每个被决定的事项：

1. 在“待决事项”表中，把“状态”改为“已决”，“决定”列写入：决定内容（日期，用户）；
2. 如果决定影响步骤的后续工作（例如选定了供应商），在交接日志末尾追加一行说明；
3. 编号不存在或已经是“已决”时，告诉用户并跳过，不要猜测。

然后运行 `make arch-check`，提交（`记录决定：D-001`）并推送到会话分支。

最后回复用户：记录了哪些决定、哪些步骤因此解除阻塞，并提示“说‘继续当前进度’即可接着做”。本命令只负责记录，不开始实现。
