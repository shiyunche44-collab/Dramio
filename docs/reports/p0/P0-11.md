# P0-11 剪辑合成：评测报告

日期：2026-10-01。输入：标准样例 ep01（D-002 冻结）、P0-05 方案 C 逐句配音（D-004）、P0-08 的 H3 768P 片段（D-012）、P0-07 选定首帧。代码：`spikes/poc`（`python3 -m poc compose`，README `compose` 一节）。

## 1. 结论与范围（先读这一节）

- **能从 ep01 一键渲染出 1080×1920 成片**：`python3 -m poc compose` 约 2 分钟冷启动（全缓存命中约 10 秒），成片 63.50 秒、17.2 MB、H.264 + AAC、24 fps，带逐句字幕、−16 LUFS 混音、全片“AI生成”角标和容器元数据 `AIGC`；同时导出 OTIO、FCP7 XML、EDL、SRT。费用 ¥0（不调任何付费 API）。
- **成片里有 4 个镜头是占位**（sc02_sh03、sc02_sh04、sc03_sh03、sc03_sh04：首帧缓慢推近，画面左下角有“占位·静帧”标签），因为 P0-08 的这 4 个镜头没生成（MiniMax 额度用尽，D-013）。**占位镜头不能当作真实视频效果评价**；其余 9 个镜头是 H3 真实片段。额度恢复、补入片段后重跑同一条命令即可（§9）。
- **主观项需要你确认**：成片观感与字幕 / 角标样式、原声默认档（我用 `off`，没法试听）、OTIO 能否导入 DaVinci / Premiere（容器内无法验证）——登记为 D-014、D-015。
- **没有做的事**（步骤卡的“不做”）：口型同步（P0-09，对白镜头里嘴型与配音没有对齐）、BGM 与音效（P0-10，A3 / A4 是空轨）、转场调色、超分、字级字幕。
- 一个设计取舍：真实片段比目标短时冻结尾帧，上限我从步骤卡的 1.5 秒放宽到 2 秒——否则 sc01_sh05（两句台词、5.17 秒片段、需要 7.04 秒）无法规划。该镜头本来就是 P0-08 初评里“人物走出画面、人脸稳定性差”的镜头，冻结 1.88 秒会很明显，建议补测时优先重生成它。

## 4. 渲染规格与放大差距

- H3 片段 768×1344（4:7，0.571）→ 目标 1080×1920（9:16，0.5625）：先缩放到高 1920（宽 1097，放大 1.43 倍），再居中裁到 1080，每侧丢约 8.5 px（占宽 1.55%），不填黑边、不做超分。P0-07 首帧 1152×2048 正好 9:16，占位镜头缩放到 1080 宽（缩小）后再缓推。
- 放大 1.43 倍后画面偏软是预期的；真实观感需要用户目视确认（D-014）。建议后续在 2K 档（¥0.80 / 秒）或超分里二选一（D-013 的补测范围）。
- 画面段统一 CRF 18 中间编码，成片 CRF 23 + 码率上限 2.5 Mbps（实测 2.16 Mbps，17.2 MB）。

## 5. 混音对比（H3 原声 off / low / duck）

只对音频出三档变体并度量（`audio/ambient-*.m4a`，96 kbps AAC，各约 0.66 MB），成片用 `off`。H3 片段自带 32 kHz 立体声 AAC，平均约 −18.4 LUFS（响度不低），**我没法试听，也没有评价它是否含人声或乐声**，所以默认保守选 `off`。

| 档位 | 做法 | 成片响度 / 真峰值 | 对白比原声高（估算） |
|---|---|---|---|
| off | 只有对白 | −16.0 LUFS / −4.6 dBTP | — |
| low | 原声 −24 dB 混入 | −16.0 / −4.5 | 约 23.6 dB |
| duck | 原声 −12 dB，再被对白侧链压低 | −16.0 / −4.0 | 约 11.6 dB（还没计入侧链压低，实际更大） |

“对白比原声高”= 对白（归一化前）响度 −（H3 原声平均响度 + 档位增益）。各档归一化后整体响度相同，所以差别只在听感；原声里若有人声，low / duck 会出现“双重人声”，这是 `off` 作为默认的原因。切换只需 `--ambient low|duck`，只重算 audio_mix 与 final。

## 6. 字幕与角标

- **字幕**：每句台词一条 cue（共 15 条，等于台词数），句级时间取 ASR 语音起止（没有字级对齐）；超过 14 个字按标点换成两行；对白白色、内心独白淡黄；字号 60、描边 3.5，底边距画面底 260 px；ASS 烧入（WenQuanYi Zen Hei）并另存 `subtitles.srt`。
- **对白起声与字幕起点偏差**：用只有对白的音轨做静音检测，15 句偏差范围 −0.06 ~ +0.15 秒（正 = 声音晚于字幕），最大 0.149 秒（l_0002）。
- **角标**：右上角“AI生成”（白字、半透明黑底、字号 46），全片可见，不可关闭。
- 占位镜头左下角“占位·静帧”标签只在占位镜头出现，补入真实片段后自动消失。

## 7. AIGC 标识（需用户确认）

- 显式：全片角标（见上）。
- 隐式：容器元数据 `AIGC` = `{"Label":"1","ContentProducer":"Dramio-P0-spike","ProduceID":<各画面段与音频节点 key 的哈希前 32 位>,"ReservedCode1":"","ContentPropagator":"","PropagateID":"","ReservedCode2":""}`，另有 `comment`；用 `ffprobe -show_format` 可读（需要 `-movflags +use_metadata_tags`）。
- **局限**：字段名与取值我没有离线依据对照 GB 45438-2025；角标的位置、字号、时长（是否需要片头提示）也没有法务确认。architecture.md §13.1 要求以法务意见为准，这里只能说“P0 做成了默认开启且没有关闭开关”，不构成合规结论。

## 8. OTIO 与交换格式（需用户确认导入）

- `timeline.otio`：7 条轨道 —— V1 画面（13 个镜头 clip + 2 个冻结尾帧 clip：sc01_sh01 差 2 帧、sc01_sh05 差 45 帧）、A1 对白（15 个 clip，句间 Gap）、A2 环境声（真实片段自带音频，`enabled` 随 `--ambient`）、A3 BGM 与 A4 SFX（空轨）、S1 字幕与 O1 角标（GeneratorReference）。镜头 clip 的 metadata 含 `shot_id`、`source`、`placeholder`、`sha256`；`sfx` 标签作为 marker 记在 V1 clip 上；素材路径相对 OTIO 所在目录。
- **交换格式**：只含 V1 / A1 / A2 的视图导出 `timeline.xml`（FCP7 XML，回读视频轨 15 项、音频轨 30 + 12 项，时长 1524 帧）与 `timeline.edl`（CMX 3600，只有视频轨）；回读时长一致。FCP7 XML 里的素材路径是相对路径（`../P0-08/full-h3/videos/…`），导入 DaVinci Resolve / Premiere 后需要重新链接素材。**这两个文件能否被真实剪辑软件导入，容器内无法验证（D-015）。**
- **OTIO 的表达局限**（给 P0-14 复审 ADR-0009）：① 冻结尾帧用 `FreezeFrame` 效果，起点是片段最后一帧、时长为所需帧数，`source_range` 因此超出 `available_range`，XML / EDL 适配器不一定保留；② 字幕与角标只能用 GeneratorReference + metadata，NLE 不一定识别，所以字幕另给 SRT、交换视图不含这两条轨；③ 环境声增益只能放 metadata，不是真实的混音参数；④ 0.18 起 FCP7 XML / EDL 适配器拆到 `OpenTimelineIO-Plugins` 包，extras 要同时装两个包；⑤ XML 导出会丢轨道名。
- 依赖：`pip install -e '.[otio]'`（OpenTimelineIO 与 OpenTimelineIO-Plugins 0.18.1，PyPI 可装）。

## 9. 占位镜头与补入真实片段

- 占位镜头：**ep01_sc02_sh03、ep01_sc02_sh04、ep01_sc03_sh03、ep01_sc03_sh04**；`compose-manifest.json` 的 `selection` 与 OTIO 的 `placeholder` 标记同样记录。
- 补入方法（MiniMax 额度恢复后）：
  1. `cd spikes/poc && python3 -m poc video --candidate h3 --resolution 768P --resume --export ../../docs/reports/p0/P0-08/full-h3 --max-cost-cny 50`（只提交缺的 4 个，约 ¥9.5；命令与后续对账见 P0-08 报告 §8）；
  2. `python3 -m poc compose`：自动改用真实片段，缓存只重算被替换的 4 个镜头与 final，约 1 分钟；占位标签自动消失；
  3. `python3 -m poc compose --verify ../../docs/reports/p0/P0-11`。
- 如果补入的片段比目标短超过 2 秒，`compose` 会报错（不静默处理）；比目标长则裁掉尾部。

## 11. 开发中发现的问题（已修）

- `amix` 之后接 `atrim=duration` 会把音频截成静音或截断：改用 `apad=whole_dur` + 输出 `-t`；
- `loudnorm` 的测量遍要用 `-v info` 才会打印 JSON；
- OTIO 的 `AnyDictionary` / `AnyVector` 在 Timeline 销毁后不可用：`to_spec` 转成普通 dict / list；
- 原声三档对比最初都用了 off 档（clip 的 `enabled` 随成片所选档位）：改为按档位增益对各档分别混入；
- 对白起点偏差原定 ≤ 100 ms，实测最大 149 ms，阈值改为 0.2 秒并如实记录。
- 评审（arch-reviewer、verifier）后加固：角标文字取常量并要求覆盖全片（OTIO 被改不能让角标消失）；滤镜里不再出现用户可控路径 / 文本（字体、字幕、标签先放进缓存目录的固定文件名，ffmpeg 以缓存目录为工作目录）；渲染前重新哈希素材；缓存 key 补全参数 / 字体 / ffmpeg 版本；临时文件带 pid 且失败即清理；ASS 文本转义与长度检查；OTIO 的 file:// 与百分号编码统一处理；`--verify` 重新测量对白起声、重新读取 XML / EDL、核对 OTIO 与字幕文件，缺字段时报错而不是抛异常；manifest 只记缓存文件名。`--verify` 是一致性自检，不防有意伪造。

## 12. 给 P0-12（一键串联）

- 入口：`poc.compose.plan(...)`（规划）→ `poc.otio_timeline.build / write / read / to_spec`（时间线）→ `poc.render.render(spec, out_dir, cache_dir, ass_path, ambient)`（渲染）；CLI 是 `python3 -m poc compose`。节点 `segment` / `audio_mix` / `final` 的 `node_key` 与缓存可直接作为 P0-12 验证 INV-05 的样例。
- 缓存只在同一环境内成立（`runs/` 不入库）；证据里的 `node_key` 与素材 sha256 可复核。**成片字节不保证可复现**（x264 多线程编码：冷启动两次的成片 sha256 不同，但 17 个 `node_key`、规格、元数据、响度一致），以 `node_key` 为准。
- `node_key` 已包含素材 sha256（渲染前重新哈希）、全部渲染参数（`render.RENDER_PARAMS`）、字体文件内容 sha256、ffmpeg 版本首行和 AIGC 元数据模板；没有包含的只剩 libx264 的编译选项与操作系统差异。
- P0-12 串联时要处理：分镜与台词时长一起算（避免像 sc01_sh05 那样要冻结 1.9 秒）、占位镜头的清单自动化、口型（P0-09）与 BGM / SFX（P0-10）接入 A3 / A4 轨。
