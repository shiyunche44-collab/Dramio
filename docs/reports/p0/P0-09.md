## 1. 结论与范围（先读这一节）

- **范围比步骤卡小**：计划测 5 个对白镜头，实际只有 3 个镜头（`sc01_sh04`、`sc01_sh03`、`sc03_sh01`）× 路线 A、B 完成，共 6 个 H3 任务。`sc03_sh02`、`sc01_sh05` 的 4 个任务在第 7 个任务被 MiniMax 拒绝：429 `2056`“已达到 Token Plan 用量上限”（提交即被拒、未创建任务、不计费），之后复测仍被拒。额度接口显示周额度还剩 21%，但视频提交仍被拒；一天内 6 个片段（¥14）把周额度从 68% 用到 21%，粗略看 100% 周额度约等于 ¥30 的视频。补测登记为 D-017。**样本只有 3 个镜头，全部是单说话人，结论只能当量级参考。**
- **H3 能在画面里说话，而且台词是对的**：6 个片段全部生成成功；片段原声过豆包 ASR，与台词的同音字折叠 CER 全为 0（M1 通过 6/6）。嘴部抽帧里有明显的张口、圆唇、露齿变化，身份稳定（agent 看缩略条的初评，**没法试听**）。
- **路线 B（参考音频）比 A（原生音画）好，但不稳定**：
  - B 的嘴部开合与音频包络相关（M3）3/3 通过，比对照高 0.38–0.72；A 为 2/3（`sc01_sh04` 比对照只高 0.1499，差 0.0001 不到 0.15 的门槛）。
  - 参考音频 **2/3 原样带出**：`sc01_sh04`、`sc01_sh03` 的片段原声与输入配音的包络相关 0.993 / 0.998，就是 D-004 的音色；`sc03_sh01` 相关只有 0.13，H3 用自己合成的声音念了台词。所以 B 不能保证保留 D-004 音色。
  - B 与 `first_frame` 互斥，片段第一帧不再是 P0-07 选定的首帧：首帧 SSIM 0.81–0.88（A 为 0.95–0.97）；人脸相似度仍高于 τ = 0.45（最小 0.58–0.62）。
- **按预设判据，没有路线达到“建议为默认”的客观门槛**：判据要求可测镜头里 M2（起声偏差 ≤ 0.20 秒）与 M3 达标 ≥ 4/5（本次只有 3 个镜头，按比例即 3/3 或至多 1 个例外）。B 的 M2 只有 1/3、A 为 0/3。M2 失败的原因不是度量坏了：6 个片段里 5 个在语音开始前 0.8 秒以上嘴就已经张合（见 §4），另有一个起声偏差 0.02 秒。这对观感是不是问题，要你看了片子才能定（D-016）。
- **推荐（待你确认）**：用 H3 出画面和口型，**配音始终用 D-004 的音轨**，按片段里检测到的语音区间重排（路线 C 的做法）。依据：C 的包络相关 0.70 / 0.69，与 A 的 0.64 / 0.72 相当，说明把配音贴回去时粗粒度的节奏同步还在；这条路线也不动 D-014（原声 off）和架构 §5.5.1 的“音频先行”。限制：C 要求配音变速在 0.8–1.25 内，`sc01_sh04` 的变速 0.78 不可行（差一点）；嘴型贴的是 H3 自己念的字音节奏，不是配音的字音节奏。
- **需要注意的时序问题**：H3 的开口时间不可控，A 为 2.72 / 2.09 / 1.56 秒，B 为 2.51 / 0.19 / 1.63 秒（5 秒片段）。提示词里有“咬紧嘴唇”“整理领带”这类先发生的动作时开口明显更晚。片段里前 1–2.5 秒是没有声音的表演，对白短的镜头会浪费时长和费用。这需要在 P1 的提示词里处理（例如明确“镜头一开始就开口”），本步没有额度验证。
- **“后期口型”没有评测**（按你的指令）：roadmap 要的“后期口型或原生音画”二选一，只覆盖了 MiniMax 内的原生音画与参考音频。若你最终认为 MiniMax 内的结果不够，架构 §5.5.2 的“后期口型”仍是未经验证的默认，需要另开补测。

读表时注意：
- **M2 的 −1.0 秒是被截断的值**：嘴部起点从语音起点前 1 秒开始找，所以 ≈ −1.0 表示“至少早 1 秒就在张合”，不是精确值。5/6 个 A / B 片段是这种情况。逐帧看（`analysis/strips/`、`analysis/curves/`）：说话前嘴部已经微张或在动，有时是情绪动作（咬唇、颤抖），有时看起来像在无声地说话。**这正是需要你看片子判断的点。**
- **M4 的失败多数与 M2 同源**（语音前 1 秒内嘴在动被算进“静音段”）。对照行的 M4 比值没有意义（例如 4.44：对照里嘴几乎不动，分母接近 0）。
- **M3 的区分度**：对照的 r0 为 0.40 / 0.01 / 0.01，其中 `sc01_sh04` 对照 0.40 高于它的替身 P95 0.36（一个假阳性，说明“高于替身 P95”不够，必须再要求“比对照高 0.15”）。A、B、C 的 r0 大多 0.55–0.78，远高于对照；这说明 H3 的嘴部节奏确实跟着音频走，**不能说明字音（viseme）对得上**。
- **C 的包络相关与 A 相当**：C 用的是 A 的画面，配音按 H3 自己语音的区间重排，嘴部节奏仍然跟配音的包络相关；C 的 `sc01_sh03` 相关 0.70、`sc03_sh01` 0.69。

## 5. 度量的修正与局限（诚实记录）

- 第一版嘴部跟踪每帧取检测分最高的脸，`sc03_sh01`（画面里有虚化的前景同事）在陆沉与前景人物之间来回切换，B 的 r0 被算成 0.18、缩略条里混着别人的嘴。改成“全片检测分最高的一次检测为起点，逐帧按位置连续性跟踪同一张脸”后，B 的 r0 变成 0.73。这一修正是看了缩略条之后做的，对所有片段统一生效；判据阈值没有改。
- 路线 C 的第一版实现有错：`atempo` 之后的时间戳让同一条 filter 链里的 `adelay` 失效，音轨被截短到 3.2 秒，当时的 C 度量（r0 0.02 / −0.34）作废；改为先把每句渲染成变速后的 wav 再延迟混合后重新评测，上表是修正后的数字。
- 嘴部开合 = 唇部关键点（106 点里的 52–71）纵向范围 ÷ 脸宽，只反映开合的节奏；不判断口型形状、不测唇齿同步（没有 SyncNet / LSE，留给 P1 质检）。
- 语音窗口的来源是 ASR 的句起止（粒度 10 ms），对照用配音自己的 ASR 起止经 compose 排进镜头。
- 3 个镜头全是单说话人，没有 `sc01_sh05`（双人轮流说话、人物走出画面）这类困难样本。

## 10. 给 P0-11 / P0-12 / P1 的建议

- **音频先行时序**：H3 的开口时间不可控（0.2–2.7 秒）。P0-12 串联时，口型镜头要在生成后用 ASR 或能量检测拿到语音区间，再决定配音放在哪里、镜头时长是否够，不能假设配音从镜头第 0.15 秒开始。
- **配音保持 D-004**：不依赖 H3 原声。重排配音时的变速范围建议先定 0.8–1.25（本步用的），`sc01_sh04` 的 0.78 说明范围可能需要放宽，是否放宽留给 P0-12 用更多样本决定。
- **提示词**：对白镜头的动作描述不要放“先做动作再说话”的内容；P1 里为对白镜头单独做提示词模板，明确开口时机。本步没有额度验证“镜头一开始就开口”这类写法。
- **B 与首帧互斥**：若首帧一致性（P0-07）比声音一致性重要，选 A；若要 D-004 音色且接受首帧偏移，选 B；两者在配音被重排（C）的前提下差别主要在首帧保真。
- **计费**：B 的音频输入是否另计费、周额度与视频提交限额的关系，需要在 MiniMax 控制台核对；P1 的模型网关要把 429 `2056` 当成账号级的“停止提交”信号（`poc` 里已经这么做）。
