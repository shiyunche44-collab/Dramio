## 6. Ark Seedance 结论：不可用

- 套餐路径 `GET /api/plan/v3/contents/generations/tasks` 免费探测 200（`total=0`），说明 Key 对套餐路径有效。
- 对空镜 `sc01_sh01`（480p、4 秒，经本地校验的合法请求）依次提交 Seedance 2.0-mini、2.0-fast、2.0、2.5，带日期的模型 ID 与 Agent Plan 文档里不带日期的别名（`doubao-seedance-2.0-mini` 等）两种写法，8 次全部 404 `UnsupportedModel`“does not support the agent plan feature”（未创建任务、不计费）；按量路径 `/api/v3` 用同一个 Agent Plan Key 返回 401（只说明这个 Key 不能走按量路径；我们没有按量付费 Key 可试）。
- 推断：当前套餐档位不含视频（套餐文档写视频只在 Large / Max 档），或需要按量付费 Key。所以“Agent Plan 能否调 Seedance”的答案是**本账号不能**；首帧是否被 Seedance 的人脸限制拒绝（图生图首帧 vs 文生图原始产物）**没有机会验证**。
- 证据：`docs/reports/p0/P0-08/smoke-seedance/`（8 次 404 的运行记录）与 `smoke-seedance/probe.json`（免费 GET 探测结果）。顺带修正：Ark 费用预估原来用首帧像素，高估约 5 倍，现用输出分辨率像素。

## 9. 事故与局限

- **探测事故**（2026-09-30）：为摸清首帧写法发了带非法图片地址的请求，接口没有在校验阶段拒绝，而是创建了任务 `447505300464052`（立即 failed，`usage` 为空）。此后不再用探测请求碰会创建任务的路径。
- **旧会话的全量运行记录丢失**：容器回收后 `tasks.jsonl` 与 calls 丢失，只剩已入库的 8 个视频。用只读任务列表按创建顺序和时长把 9 个任务对回镜头（时长逐一吻合），并重新下载比对 sha256 确认全部一致，重建 `tasks.jsonl`。教训：`tasks.jsonl` 要随每个任务提交立即提交到分支。
- 人脸相似度沿用 P0-07 的度量局限（侧脸、小脸低估）；运动量只是亮度差代理；初评未逐帧检查。
- 费用是文档单价估算，需要你在控制台核对账单；账单若与账本不一致，以账单为准。
- 已知局限（P0 spike，不修）：费用保险只约束单次运行，不累计多次运行；`tasks.jsonl` 无文件锁，不要同时启动两个 `--resume`；`--verify` 核对的是账本而不是 `calls.jsonl`（后者在旧会话丢失后不完整）；`node_key` 没有包含 `aigc_watermark`、`prompt_expansion_mode` 等参数（P1 做生成节点时要补进幂等键的输入）。
- 评审后修正的行为：额度用尽 / 账号级错误会中止整次运行；`--resume` 不再重复追加记录、沿用旧任务不重复计费、非审核类终态失败的任务会重新提交；任务成功后先记费用再下载。
