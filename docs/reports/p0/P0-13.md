# P0-13 规模抽测

> 3 集 × `python3 -m poc run --video placeholder`（`spikes/poc/scripts/p0_13_batch.sh`），汇总 `poc/scale_summary.py`，人脸相似度 `poc face`（τ = 0.45，错人 < 0.30）。证据 `docs/reports/p0/P0-13/`（2.6 MB，不含原始成片，只有 360p 预览）。

## 1. 结论（含诚实的边界）

| 项 | 结果 |
|---|---|
| 规模 | 3 集、**63 个镜头**、35 句台词、10 个角色、195.5 秒成片（每集 62.9 / 69.1 / 63.5 秒）；3 集全部退出码 0，`run --verify` 逐集通过；热运行 3 集 61–67 个节点全命中、¥0、各 0.5 秒 |
| 费用 | 冷运行合计 **¥27.94**（每集 ¥8.6–10.1，每镜头 ¥0.44，每分钟成片 ¥8.6）；其中 Ark 定妆 + 首帧 ¥27.14 是 Agent Plan **等价费用，不实付**，真实付费只有 DeepSeek + 豆包语音约 ¥0.8 |
| 耗时 | 串行共 6359 秒（每集 33–39 分钟，每镜头约 101 秒）；**首帧占 73%**（4632 秒，73 秒 / 张），compose 9%，定妆 10% |

## 2. 四个问题

### Q1 角色一致性能否稳定达标：**部分，只覆盖首帧**

| 集 | 实例 | 可度量 | 中位 | P10 | P90 | < 0.45 | < 0.30 |
|---|---|---|---|---|---|---|---|
| ep1 | 24 | 22 | 0.691 | 0.359 | 0.798 | 3 | 1 |
| ep2 | 23 | 21 | 0.560 | 0.38 | 0.72 | 6 | 2 |
| ep3 | 22 | 15 | 0.613 | 0.351 | 0.742 | 4 | 0 |
| 合计 | 69 | 58 | 0.649 | 0.343 | 0.782 | 13（22%） | 3 |

（实测，来源 `P0-13/ep*/faces.json`，bank 口径，分位数用线性插值（numpy 默认，小样本下 P10 对个别实例敏感），参考图是各集自己的主图 + neutral 特写，`--pick largest`。）

- 对比 P0-07（`ref2`，13 个镜头、2 个角色）：中位 0.56、92% ≥ τ。本次中位更高（0.649），但 ≥ τ 的比例降到 78%。下尾变差主要来自**双人镜头**：13 个不达标实例里 12 个出在两个角色同框，而且多数脸像素较小（47–160 px）。
- 另有 **11 个实例（16%）“无脸”未检出**，不在上表分母里，它们可能是真不达标（脸被遮挡 / 太小 / 背影），所以 22% 是**已度量实例中的占比**，不能当作上界；参考图与首帧同出自 Seedream 也可能使分数偏高。
- **没测到的**：视频阶段的漂移（占位只是首帧缓推，本身不改变脸）；跨集一致性；侧脸、小脸被 arcface 低估的部分（P0-07 已说明），侧脸、小脸被低估会让 22% 偏高；τ 来自 P0-07 的 2 个角色，没有同性别负样本，不能外推到所有人物。
- 结论：单人镜头基本稳定，**双人镜头需要“多候选 + 打分选优”**（P1-12），不能靠单次生成保证。

### Q3 口型能否达到可播出水平：**P0-13 没有新增数据**

占位镜头没有人在说话，所以无法测口型。仅给出范围：3 集共 35 个对白镜头（占 56%），其中**双人同框的对白镜头 6 个**（ep2 的 4 个、ep3 的 2 个，占对白镜头 17%）。P0-09 只测了 3 个单人镜头（路线 C 候选，用户没有逐片段评分），双人轮流说话的难例（D-017）仍未测。**沿用 P0-09 / D-016 的结论**，不在此补充。

### Q4 哪个环节返工最多：**首帧（自动代理指标）**

| 环节 | 自动返工信号 | 数据（3 集） |
|---|---|---|
| keyframe | 度量不达标 | 13 / 58 个可度量实例 < τ（22%）；重抽 2 个镜头过线 1 个 |
| shots | LLM 修复轮 | 3 集里 2 集需要 1 轮修复（script 3 集都是 0 轮） |
| 台词与镜头时长 | 台词比 `hint_s` 长，合成时自动延长 | 28 / 63 个镜头有警告（44%：ep1 6、ep2 12、ep3 10），但**多数超出很少**：超出 > 0.3 秒的 10 个（16%），> 0.5 秒的 8 个；最大 1.92 秒；超出均值在延长镜头上为 0.17 / 0.47 / 0.34 秒（全集均值 0.16 秒）。警告按文本“台词需要”计数，没有阈值 |
| 网络 / 供应商 | 重试 | 3 次，¥0.64 |
| costume / tts / script | — | 无失败，无自动返工 |

口径：**自动代理指标**，不含人眼认为不可用的返工（那需要用户评价，见 D-019）。其中最值得注意的是“**台词与分镜时长没有闭环**”（44% 的镜头有超出，16% 超出 > 0.3 秒）：现在分镜时长（`hint_s`）与配音时长没有闭环，靠合成延长兜底，视频生成时会按 `hint_s` 生成再冻结最后一帧（P0-11 已见 `sc01_sh05` 冻结 1.9 秒）。P1 需要“先配音再定镜头时长”。

## 4. 与步骤卡的差异

- **重抽实验未完成**：计划 9 个镜头，只完成 ep1 的 2 个，原因见 §6。
- **证据不含原始成片**：每集 15–20 MB，只放 360p 预览（`P0-13/ep*/preview-360p.mp4`，约 0.6 MB）；原始 `final.mp4` 在 `spikes/poc/runs/p0-13/`（不入库，容器回收后丢失）。

## 5. 自动化过程中发现的缺口

1. **音色池只有 2 个**：10 个角色里 4 个复用了同性别的同一音色（ep1 的 suning、ep2 的 linwan 和 luchen、ep3 的 luzhenting），同一场戏里两个女声会听起来像同一个人。
2. **双人镜头一致性**（Q1）和**分镜 / 配音时长不闭环**（Q4）是最明显的质量缺口。
3. 首帧 73 秒 / 张、串行：整集 25–30 分钟只在首帧；P1 需要并发和批量。
4. Seedream 无 seed，`--reroll` 只改缓存 key，结果是否不同取决于供应商随机性（重抽 3 个实例有 1 个明显变好、1 个基本不变、1 个变差——样本太少，不能说明 `--reroll` 有无效果）。

## 6. 阻断：Ark Agent Plan 月度额度用尽

重抽实验的第 2、3 集提交首帧时返回 HTTP 429 `AccountQuotaExceeded`：“已超出月度用量额度，将于 **2026-11-01 23:59:59 +0800** 重置”。这是账号级错误，`run` 按设计退出码 1（图像没有降级路径）。含义：

- **在重置前（或升级套餐前），无法再生成任何新的定妆图 / 首帧**；已缓存的节点仍可热运行。
- `calls.jsonl` 里这 6 次被拒的请求按保守估算各记了 ¥0.36（共 ¥2.16），**实际未计费**；`reroll/calls-ep2.jsonl`、`reroll/calls-ep3.jsonl` 保留了记录，上面的费用合计未包含它们。
- 对 P0-14 的影响：P0-14 是复盘与文档，不需要新生成；但任何补测（D-013 / D-017 / 重抽）都要等额度。
