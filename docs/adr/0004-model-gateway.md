# ADR-0004：所有模型调用经由模型网关

- **状态**：Proposed
- **日期**：2026-09-30
- **决策人**：@shiyunche44-collab
- **关联**：架构文档 §7；不变量 INV-01、INV-07

## 背景

图像、视频、语音、LLM 模型按月迭代，供应商会涨价、限流、下线。如果业务代码和 Worker 直接调用各家 SDK，换模型就要改遍全仓库，成本也无法统一计量。

## 决策

- 业务代码、Workflow、Worker 只调用**能力**（如 `video.i2v`、`audio.tts`），由模型网关（`services/model-gateway`）选择具体模型。
- 供应商 SDK 只允许出现在模型网关内；模型 ID 只出现在网关的路由配置中。
- 网关统一负责：路由、限流、熔断与降级、幂等、成本计量入账、区域合规路由。
- 新模型上线前必须在评测集（`evals/`）上跑回归，通过后灰度放量。

## 备选方案

| 方案 | 不选的原因 |
|---|---|
| 业务直连各家 SDK | 换模型改动面大；无法统一计量、限流和降级 |
| 使用第三方聚合平台 | 覆盖不了自建模型和国内供应商；路由与计量策略受制于人 |

## 后果

- 正面：换模型只改网关配置和适配器；成本、成功率、延迟在一处可见。
- 负面：网关是关键路径，需要高可用；新能力要先在网关中抽象。
- 约束：`tools/archcheck` 的 `vendor-sdk`、`model-id` 规则在 CI 中强制执行；生产环境用 K8s NetworkPolicy 限制只有网关 Pod 能访问模型供应商域名。

## 复审条件

网关成为性能或研发效率瓶颈（例如某类调用的额外延迟不可接受）。
