# ADR-0006：基于 node_key 的生成缓存与增量重算

- **状态**：Proposed
- **日期**：2026-09-30
- **决策人**：@shiyunche44-collab
- **关联**：架构文档 §6.2、§6.3；不变量 INV-05

## 背景

创作过程中修改频繁：改一句台词、换一个造型、调整一个镜头。如果每次都整集重跑，成本和时间都不可接受；如果靠人工判断“哪些要重做”，一定会出错。

## 决策

- 每个生成节点计算缓存键：
  `node_key = hash(节点类型, 能力/模型版本, 参数, prompt 模板版本, 上游产物哈希, DramaIR 相关字段哈希)`。
- `node_key` 相同则直接复用已有产物；上游变化时下游节点标记为 Stale，只重算受影响部分。
- 被人工锁定（Locked）的节点不受上游变化影响。
- `node_key` 同时作为调用模型网关的幂等键。

## 备选方案

| 方案 | 不选的原因 |
|---|---|
| 整集重跑 | 成本随修改次数线性增长 |
| 人工标记需要重做的镜头 | 容易遗漏，且无法自动化 |

## 后果

- 正面：修改成本与影响范围成正比；重复请求零成本；重试天然幂等。
- 负面：新增节点类型时必须正确声明参与哈希的输入，漏掉会导致错误复用。
- 约束：节点类型通过节点 SDK 注册，SDK 强制声明输入；缓存命中率作为架构健康度指标持续监控。

## 复审条件

缓存命中率长期偏低，或出现因 node_key 设计错误导致的错误复用事故。
